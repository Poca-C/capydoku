# 插页广告客户端合同 · Demo v1

依据原始 Word V1.3 的 [364]、[379–381]、[425–429]、[443–448]、[451–452]。索引指 Reference/Original/document.txt 中的正文块，不是页码。

## 已确定的客户端行为

- 只在胜利结算点击下一关或返回首页后按当前局配置请求。失败、教学、权限及其他弹层中不插入广告。
- 请求前保存本次胜利已处理标记、频次计数和原始 offer；同一胜利加载失败、重进或重复点击不再请求。
- ready 和调用 present 只表示准备／请求。适配器明确回调 started 后，才记录实际展示并进入广告音频状态。
- 加载超时、无填充或展示失败继续原操作。加载计时器不限制已就绪广告的展示时长。
- 插页不发道具、生命或其他奖励。reward_amount 为 0，reward_type、buff_type 为空，所有 ad_result 的 reward_granted 为 false。
- 第 10 关首次通关走“结算 → 插页结束 → Challenge → 第 11 关”；选择首页则回首页。
- 在后台收到终态，先保存结果与原导航意图，回前台才导航。冷启动先显示首页；选择继续后恢复已确认的下一关／Challenge 意图。冷启动已满足首页目的地。
- 没有收到终态的中断不会补造 completed，也不会重新播放同一胜利广告。

## 事件与恢复

ad_offer_shown 和 ad_result 共用 offer_id，并保留请求时的用户、统计会话、关卡、配置版本、环境和适配器元数据。每个实际事件第一次发生时确定 event_id 和 event_time，存入 win-ad-state 的待发送队列。成功进入本地分析队列后才确认删除；重启和丢确认重试复用原事件，不重新生成身份或时间。

胜利处理标记是“本次资格已处理”，不代表实际展示；展示率只能使用真实 started。后台切换不会产生第二个 started，过期回调不能关闭新广告。游戏保存的异步确认只清理该次保存对应的导航意图。

保存失败会保留内存中的待发送事件并在后续前后台或同意入口重试；问题可从诊断导出的 interstitialRecordingError 查看。两个持久化通道均未写入成功就被杀进程，不能保证恢复未落盘的事件。测试中的冷恢复和文件写失败，不等同于真实 SDK 或精确指令间的系统杀进程测试。

## 明确临时的映射

| 字段／信号 | Demo v1 映射 | 正式接入要求 |
|---|---|---|
| placement_id | demo_interstitial_win_v1 | 原文未列插页枚举，需确认后由适配器提供；不冒用 hint/revive |
| normally closed | completed | 仅表示正常结束展示流程，不据此宣称完整观看；需确认 SDK 终态合同 |
| skipped | skipped | 适配器明确区分提前结束 |
| failed / timedOut | failed，加对应错误码 | 真实错误分类由 SDK 适配器提供 |
| network / ad_unit_id | Mock 为 simulation / internal-demo；未配置适配器为 unconfigured | 真实环境提供实际平台与广告位标识，不得沿用测试标识 |
| 冷却起点 | 本次请求被持久接受时 | 沿用当前 Demo 行为，需冻结正式口径 |

临时映射不会改变冻结配置文件或冒称正式 Pawdoku 值。正式适配器必须在请求前提供经确认的元数据；若聚合网络只能在展示回调确定，需在联调时补明确的回调元数据合同，不能用默认值伪装真实平台。

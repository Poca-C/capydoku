[16] 核心爽点：

[17] • 首次操作门槛低。新手引导直接提示点击目标格，体验记录中约 3 秒即可完成第一次有效操作。

[18] • 规则数量少，但行、列、颜色区域和相邻限制能够形成连续推理。每放置一只卡皮巴拉都会缩小其他位置的选择范围，产生明确的解题推进感。

[19] • 失败通常发生在接近通关时，玩家容易产生“只差一点”的判断，因此具有较强的重试动机。

[20] • 连续正确操作会显示 Nice、Great、Excellent 等 Combo 反馈；过关后显示无失误、击败玩家比例等结果反馈，强化即时成就感。

[21] • 提示、复活都可承接激励广告，奖励内容与当局目标直接相关。

[22] • 主题替换不会影响核心机制。猫可替换为卡皮巴拉，颜色区域可解释为不同的休息区域，玩法仍然成立。

[23] 主要理解难点：

[24] • “卡皮巴拉周围的 9 个格子不能出现其他卡皮巴拉”容易被误解。准确规则是以卡皮巴拉所在格为中心，周围 8 格均不能放置另一只卡皮巴拉，包含四个斜角；远距离同一斜线不受限制。体验记录中约 2 分钟才完全理解该规则。

[25] • 参考产品在部分阶段会减少开局确定信息。Capydoku 不写死固定关卡号或固定单格区域，具体 Opening State 由 Difficulty Target 和 Generator 生成，并由 Solver 验证其难度与可解性。

[26] • 每关只有 3 次错误机会，但玩家若跳过规则说明，可能直到第一次错误后才注意到限制。体验记录中主动体验模式在第 3 关首次失败。

[27] 体验较差的问题：

[28] • 工具提示如果直接给出答案，会缩短思考过程。提示应优先解释排除原因，再高亮下一步；“直接给结果”保留为单独的广告工具。

[29] • 广告入口出现较早。第 1 关开始即在工具按钮上展示奖励广告入口，第 2 关可通过看广告获得工具加成；被动广告和 Rank 奖励在第 11 关出现。之后每关会弹出广告。

[30] • 系统自动为不符合条件的格子打叉会削弱玩家的推理参与感。本项目取消自动打叉，叉号只由玩家手动添加或取消。

[31] 本项目第一阶段确定的对标取舍：

[32] • 核心规则、工具逻辑、失败与复活流程、结果反馈、Rank 开启节点、广告承接位置及难度体验以 Pawdoku 为主要参考；具体棋盘由自研 Generator 生成。

[33] • 开局确定信息由每关 Difficulty Target 控制。新手阶段应提供足够的确定信息，帮助玩家从明确突破口开始推理，但不得写死具体坐标或固定棋盘。

[34] • 随关卡推进可逐步减少开局确定信息；Generator 必须按目标 Forced Move Density 和 Reasoning Depth 生成清晰突破口，并通过 Solver 验证，不要求固定单格颜色区域。

[35] • 棋盘不自动生成叉号。玩家通过单击格子或横向、纵向滑动手动添加 X，再次单击 X 可撤销。

[36] • 视觉主题使用卡皮巴拉，界面语言使用英文；UI 的布局密度、信息层级、按钮位置、弹窗节奏和动效反馈按 Pawdoku 的体验进行高还原，所有可识别品牌与美术资产使用本项目原创内容。

[38] 二、游戏玩法说明

[39] 2.1 玩法简介及名词解释

[40] 玩法简介：本游戏是一款以卡皮巴拉为主题的区域逻辑解谜游戏。玩家需要根据行、列、颜色区域和相邻限制，逐步排除不可能的格子，找出本关全部卡皮巴拉。棋盘尺寸随关卡提升，由小棋盘逐步扩展至大棋盘；界面持续显示本关卡皮巴拉数量、剩余生命值、分数和两类道具。

[41] 基础规则：

[42] • 每一行只能有 1 只卡皮巴拉。

[43] • 每一列只能有 1 只卡皮巴拉。

[44] • 每一个颜色区域只能有 1 只卡皮巴拉。

[45] • 任意两只卡皮巴拉不能相邻。以已确认卡皮巴拉所在格为中心，其周围 8 个格子均不能出现另一只卡皮巴拉；远距离同一斜线不受此规则限制。

[46] • 系统不得因为玩家找到卡皮巴拉而自动为其他格子生成 X。普通排除标记必须由玩家操作；只有玩家主动使用提示道具并点击 Apply 后，系统才可按提示内容批量生成 X。

[47] 核心解题循环：

[48] 玩家确认一只卡皮巴拉后，重新检查该卡皮巴拉所在行、所在列、所属颜色区域及周围 8 格，将这些位置从其他颜色区域的候选格中排除。

[54] 关卡合法性硬性要求：

[55] • 每关必须只有一个最终解。

[56] 名词解释：

[57] • 颜色区域：由一种相同底色组成的一个或多个格子，每个颜色区域对应且仅对应 1 只卡皮巴拉。

[58] • 候选格：在当前棋盘状态下，尚未被行、列、颜色区域或相邻规则排除的格子。

[59] • 确定卡皮巴拉：玩家双击格子后提交的位置；系统立即判断该位置是否正确。

[60] • X 标记：玩家认为不可能存在卡皮巴拉的排除标记，可由玩家单击、横向或纵向滑动添加，也可再次单击撤销。

[61] • 生命值：每关的容错次数。玩家提交错误的卡皮巴拉位置时扣除 1 点，全部耗尽时挑战失败。

[62] • Apply：提示道具弹窗中的确认按钮。点击后才将建议的排除结果应用到棋盘。

[126] 2.4 玩家操作方法

[127] 1. 双击确认卡皮巴拉：用户可双击任意可操作格子，包括未标记格和已标记 X 的格子。系统将该格提交为“确认卡皮巴拉”并立即校验。判断正确时，清除该格原有 X、显示卡皮巴拉并更新进度；判断错误时，不放置卡皮巴拉并扣除 1 点生命值。

[128]  IMAGES: image19.png

[129] 参考图 1：双击正确时，展示开心的卡皮巴拉动态，并产生星星特效增加被找到卡皮巴拉的数量，双击错误时，展示卡皮巴拉摇头，有一个爱心撕裂变成红色 X的特效。

[130] 2. 单击添加或撤销 X：用户单击未标记格子，为该格生成 X；再次单击带 X 的格子，撤销该 X。此操作只改变玩家的排除标记，不触发答案判断，也不扣除生命值。

[132] 参考图 2：单击已选择的X后撤销选择，再次单击后继续生成 X。

[133] 3. 横向或纵向滑动批量标记：用户从可操作格开始，沿同一行或同一列滑动，系统为手指经过的多个格子连续生成 X。斜向移动不触发批量标记；已经确认的卡皮巴拉格和系统锁定的教学目标格不可被覆盖。

[134] 4. 双击优先级：当系统识别到双击时，应取消该次点击可能产生的临时 X，并按“确认卡皮巴拉”处理，避免同一手势同时触发标记与提交。

[135] 5. 提示 Apply：使用“提示建议”后，棋盘先展示待应用的 X 预览。只有用户点击 Apply，系统才批量写入这些 X；关闭提示层时保持原棋盘不变。

[136] 6. 操作反馈：每次有效点击、双击、滑动、道具执行、生命扣除和关卡结算均提供清晰的视觉反馈；正确与错误反馈不得依赖颜色作为唯一识别方式。

[138] 三、关卡设计

[139] 3.1 关卡生成总原则

[140] Capydoku Level 1–150 参考 Pawdoku 的难度曲线和节奏，由自研 Generator 重新生成具体关卡；所有关卡通过 Solver 和 Difficulty Filter 验证。Level 151 起进入自有 Procedural Difficulty Loop。

[141] Level 1–150 采用 Difficulty Curve Mirroring + Procedural Level Generation。项目镜像参考游戏的难度体验，不镜像具体关卡数据。策划仅为每关配置 Difficulty Target，技术关卡生成器负责生成棋盘，Solver 负责验证合法性、唯一解和难度指标。

[142] 允许参考的难度维度：

[143] • Board Size Curve（棋盘尺寸曲线）

[144] • Region Count 与 Region Complexity（区域数量与区域复杂度）

[145] • Forced Move Density 与 Candidate Density（强制步密度与候选密度）

[146] • Reasoning Depth、Logical Step Count 与 Solve Time（推理深度、逻辑步数与解题时间）

[147] • Error Risk、Hint Pressure 与 Fail Pressure（错误风险、提示压力与失败压力）

[148] • Hard Level Frequency 与 Recovery Level Position（高难关频率与恢复关位置）

[149] 禁止直接复制的内容：

[150] • Region Map、Region Coordinates 与 Region Shape 的具体数据

[151] • Capybara / 卡皮巴拉答案坐标与 Answer Pattern

[152] • Exact Opening State 与 Exact Breakthrough Position

[153] • Pawdoku 的原始关卡文件、源代码和美术资源

[186] 3.7 生成与筛选流程

[187] Generator 不要求一次精准命中目标。标准生产流程为：

[188] Generate Many → Solver → Difficulty Filter → Similarity Filter → Select Best Match

[189] 每个 Difficulty Target 默认生成 100–500 个 candidates，数量由目标 Band、通过率和生成预算配置。系统先删除非法或非唯一解候选，再按难度区间筛选，之后执行本产品历史关卡与跨产品相似度检查，最后选择与目标值距离最小且质量分最高的候选。

[190] 每批次必须保留：

[191] • Difficulty Target 与 Profile 版本。

[192] • Generator 版本、Generation Seed 与候选批次编号。

[193] • 候选总数、各过滤阶段淘汰数量及淘汰原因。

[194] • 最终入选 Puzzle、Solver Report、Difficulty Report 与 Similarity Report。

[205] EagleDoku

[209] 3.10 Cross-Game Similarity Check

[210] 每个候选关卡生成 Fingerprint，并同时与本产品历史关卡和同系列其他产品的已上线或待上线关卡比较。Fingerprint 至少包含以下字段：

[211] • grid_size

[212] • region_graph

[213] • region_size_distribution

[214] • answer_pattern

[215] • opening_state

[216] Similarity Engine 对结构、区域分布、答案排列和开局信息进行加权比较。完全相同的 Region Graph、Answer Pattern 或序列化棋盘应执行硬拒绝；综合 similarity 高于配置阈值时 Reject 并重新生成。阈值由技术与策划通过样本复核后写入 similarity_config，不在单关数据中手工调整。

[217] Similarity Report 至少记录 matched_game、matched_level_id、similarity_score、matched_dimensions、threshold、decision 和 checker_version。目标是让同系列产品保持一致的难度体验，同时避免玩家感受到关卡仅替换了动物主题。

[218] 3.11 上线数据与验收

[219] 每个上线关卡必须交付以下可追溯数据：

[220] • Difficulty Target 与 Difficulty Profile。

[221] • 最终 Puzzle 数据、Generation Seed 与 Generator 版本。

[222] • Solver Report 与唯一解证明结果。

[223] • Difficulty Filter 结果及与目标区间的偏差。

[224] • 本产品历史相似度与 Cross-Game Similarity Report。

[225] • Tutorial 关对应的动态教学步骤映射（仅教学关）。

[226] 验收以 Profile、Solver Report 和过滤报告为准，不以 Pawdoku 某一具体棋盘、坐标或开局状态作为逐格比对标准。测试环境应支持按 seed 重建关卡，确保缺陷可以稳定复现。

[236] 四、美术设计

[237] 4.1 美术风格

[238] 整体方向：游戏采用轻松、治愈、明亮的休闲益智风格。整体视觉以 2D 插画和扁平化 UI 为主，参考图中的奶油白背景、暖橙色主按钮、棕色文字、柔和圆角和轻阴影，形成温暖、低压力的卡皮巴拉主题体验。

[239] 2D 视觉范围：

[240] • 卡皮巴拉头像、规则图示、格子中的卡皮巴拉状态、X 标记、道具图标、按钮、弹窗、签到日历和首页装饰均使用 2D 资源。

[241] • 卡皮巴拉造型使用大头、圆脸、短口鼻和清晰表情的卡通比例，保证缩小到棋盘格内仍能快速识别；不同状态可通过耳朵、眼睛、嘴型和姿态变化表达。

[242] • 界面背景使用低饱和奶油白或浅暖灰，允许以低透明度棋盘格、卡皮巴拉剪影或爪印作为纹理，纹理不得影响按钮和文字识别。

[243] • 主色使用暖橙色，辅助色使用棕色、米白和低饱和彩色区域；危险、错误和生命扣除使用红色或橙红色，但同时配合图标、抖动或文字，不只依赖颜色。

[244] • 棋盘颜色区域保持多色区分，颜色之间需要有足够明度或色相差异；X 使用高对比白色，卡皮巴拉头像需高于底色显示。

[245] • 字体使用圆润、粗笔画的英文无衬线字体；标题、按钮和数值采用粗体，正文与说明文字保持较高可读性。

[246] 3D 使用范围：

[247] • 3D 不用于核心棋盘、常驻角色、按钮或可交互场景，仅用于短暂动画特效和奖励表现。

[248] • 可使用带体积感的礼盒、爪印牌、光效、粒子、彩带、弹跳或旋转道具等轻量 3D／伪 3D 表现，用于签到领取、通关、连胜、奖励到账和难度提升提示。

[249] • 3D 特效时长应短，不遮挡需要继续操作的棋盘；低性能设备可关闭粒子、景深和复杂阴影，并自动降级为 2D 序列帧。

[250] • 3D 材质需延续 2D 主视觉的柔和圆角、暖色和低反差质感，避免写实毛发、强金属反射或与界面不一致的真实光照。

[251] 动效原则：

[252] • 点击按钮采用轻微缩放回弹；正确找到卡皮巴拉时头像弹出并伴随柔和光圈；错误时格子短暂抖动并扣除生命值。

[253] • 弹窗从中心缩放出现，背景增加半透明深色遮罩；关闭时反向缩放或淡出。

[254] • 签到、礼物、通关和 Combo 可使用更明显的跳动、闪光和粒子，但不得延迟下一步操作或强制播放过长动画。

[255] 4.2 UI设计及交互操作

[256] 总体要求：界面使用英文，页面结构、控件尺寸、圆角、层级、弹窗样式和交互反馈参考所提供的视频与图片。移动端采用竖屏布局，并适配刘海、状态栏和底部安全区域。

[258] • 首页（Home）。

[259] • 游戏页（Gameplay）。

[260] • 设置弹窗（Settings）。

[261] • 签到页（Daily Check-in）。

[262] • 提示弹窗、激励广告加载／播放状态、胜利／失败结算和难度提升提示等游戏流程弹层。

[263] • 不制作 Profile／头像选择页，不提供昵称编辑、头像切换和头像框功能。

[313] 五、音效音乐

[314] 总体要求：音频范围、音频资源、触发条件、播放时机、延迟、音量、循环、淡入淡出及并发规则均与解包原游戏一致。本项目只将角色主题替换为卡皮巴拉，不重新配音，不改动原音频节奏，不额外添加音效。

[315] 音频范围：

[316] • 背景音乐。

[317] • 通用点击音效。

[318] • 单击格子并生成 X 的音效。

[319] • 横向或纵向连续滑动、连续标记多个 X 的连拍音效。

[320] • 再次单击 X 并撤销标记的音效。

[321] • 双击正确找到卡皮巴拉的音效。

[322] • 双击错误格子并损失生命值的失败音效。

[323] • 连续正确操作时的 Nice、Great、Excellent 语音／音效。

[324] 1. 背景音乐：直接使用解包原游戏的背景音乐，并保持原有的适用页面、关卡播放范围、默认音量、循环点、开始与停止条件、切换方式及淡入淡出效果。

[325] • 进入页面、进入关卡、退出关卡、暂停、播放广告、广告结束及应用切回前台时，背景音乐的暂停、恢复或重播行为与解包原游戏一致。

[326] • 背景音乐由 Settings 中的音乐开关控制；开关即时生效并保存用户选择，重新启动游戏后保持上次设置。

[327] 2. 通用点击音效：用户点击解包原游戏中已配置点击音效的有效按钮时播放一次，包括首页、关卡、返回、设置、关闭、Apply、Confirm、Restart、签到及其他既有交互入口。具体按钮映射与解包原游戏一致。

[328] • 禁用按钮、被遮罩覆盖的控件、无效点击及输入锁定状态是否播放声音，严格沿用解包原游戏，不统一新增反馈音。

[329] • 连续快速点击时的防重复播放、最小间隔和最大并发数与解包原游戏一致。

[330] 3. 单击 X 音效：用户单击可操作格子并成功生成一个 X 时播放一次。操作未生效、格子不可操作或触点未形成有效单击时不重复触发，具体表现与解包原游戏一致。

[331] 4. 连拍 X 音效：用户在同一行或同一列滑动并连续标记多个格子为 X 时，播放解包原游戏的连拍 X 音效。逐格触发、连续循环、播放节奏、音效叠加和停止条件均沿用原实现。

[332] • 只对实际新增的 X 产生声音；经过已有 X、卡皮巴拉格或不可操作格时，按解包原游戏的规则处理。

[333] • 滑动结束、手指离开屏幕、操作被打断或棋盘进入输入锁定状态时，连拍音效按原规则停止。

[334] 5. 取消 X 音效：用户再次单击已有 X 并成功撤销该标记时播放一次。若撤销操作未生效，则不额外播放声音；快速连续撤销时的播放间隔与解包原游戏一致。

[335] 6. 双击正确找到卡皮巴拉音效：用户双击任意可操作格子并正确找到卡皮巴拉时立即播放一次，同时执行卡皮巴拉头像显示、进度更新及对应视觉反馈。若双击的格子原本带有 X，音效优先级及是否同时播放取消 X 音效与解包原游戏一致。

[336] 7. 双击失败音效：用户双击非卡皮巴拉格子、判定错误并实际扣除一次生命值时播放一次。每次有效扣血只触发一次失败音效；输入锁定、结算中或未发生扣血时不重复触发。

[337] 8. Combo 音效：连续正确操作达到解包原游戏规定的反馈条件时，依次触发 Nice、Great、Excellent 音效。触发阈值、出现顺序、播放延迟、与画面文字同步时机以及 Combo 中断和重置条件均与解包原游戏一致。

[338] • Nice、Great、Excellent 直接使用解包原音频，不翻译、不重新录制，也不叠加额外欢呼、掌声或奖励音效。

[339] • 若解包原游戏将其归类为语音，则由 Settings 中的语音开关控制；若归类为音效，则保持原有音频分组和开关映射。

[340] 设置开关与播放控制：

[341] • 音乐开关控制背景音乐；音效开关控制通用点击、单击 X、连拍 X、取消 X、双击成功及双击失败等效果音。

[342] • 语音开关控制 Nice、Great、Excellent 等语音内容，最终以解包原游戏的音频分组为准；震动开关仅控制震动，不影响音频播放。

[343] • 各开关的默认状态、首次启动状态、本地保存方式、静音后恢复方式和音量层级均与解包原游戏一致。

[344] • 弹窗、动画、奖励到账、倒计时、页面切换及广告流程不额外增加游戏音效；广告自身声音由广告 SDK 按其原有逻辑控制。

[345] 验收标准：

[346] • 逐项核对解包原游戏的音频文件、时长、触发事件、播放次数、触发延迟、音量、循环方式和音频分组，结果保持一致。

[347] • 分别在音乐、音效、语音开关开启和关闭的状态下验证全部音频事件，开关控制范围与解包原游戏一致。

[348] • 验证快速点击、连续滑动、双击、暂停恢复、广告前后及前后台切换场景，不得出现重复播放、声音叠加失控、漏播或错误恢复。

[349] • 最终安装包不得包含本节范围以外的新音频文件，也不得新增解包原游戏不存在的音频触发点。

[350] 六、数据采集（V1 保留最小必要埋点与本地存档，不采集逐格操作等高频明细）

[351] 第一版数据方案以“能判断用户是否理解玩法、关卡是否卡住、玩家是否持续游玩、广告是否被接受”为目标。看板只保留四块，埋点只保留 12 个事件，不在第一版加入棋盘逐格点击、每次 X 操作、Combo 或页面曝光等高频明细事件。

用于新增用户和留存 Cohort。重复启动不得再次上报。
session_start
应用进入前台并形成一次有效会话时上报。
entry_source:enum（cold_start／resume）
生成新的 session_id。后台超过项目设定超时时长后再返回，视为新 Session。
session_end
应用进入后台、退出或 Session 超时结算时上报。
duration_sec:int；end_reason:enum（background／quit／timeout）
同一个 session_id 只结算一次；异常退出可由下次启动补记。
tutorial_start
新手引导第一步实际展示时上报。
tutorial_id:string
V1 仅记录整段引导开始，不记录逐步骤曝光。
tutorial_end
新手引导完成或退出时上报。
tutorial_id:string；result:enum（complete／quit）；duration_sec:int
完成率只计算 result=complete。
level_start
棋盘可操作、关卡正式开始时上报。
attempt_no:int；grid_size:string；is_tutorial:bool；direct_find_visible:bool；direct_find_inventory:int；hint_inventory:int；level_start_free_available:bool
棋盘可操作时上报一次，用于核对 Pawdoku 逐关配置是否正确加载；看广告返回或切前后台不得重复上报。
level_end
本次尝试胜利、生命耗尽失败或主动退出时上报。
result:enum（win／lose／quit）；duration_sec:int；attempt_no:int；fail_reason:enum；life_remaining:int
fail_reason 建议值：life_zero／quit／unknown；胜利时为空。
level_restart
失败后重试，或在设置中主动 Restart 并生成新棋盘时上报。
restart_reason:enum（after_fail／manual）；previous_fail_reason:enum；next_attempt_no:int
必须指向同一 level_id；新尝试随后正常触发 level_start。
ad_offer_shown
用户点击激励广告入口并发起广告请求时上报。
offer_id:string；placement_id:enum；reward_type:enum；buff_type:enum；reward_amount:int
placement_id：direct_find／hint／revive／level_start_free／coin_double。入口被点击并发起广告请求时上报，offer_id 串联广告漏斗。
ad_result
同一次激励广告开始、完成、跳过或失败时上报。
offer_id:string；placement_id:enum；status:enum（started／completed／skipped／failed）；reward_granted:bool；error_code:string
同一 offer_id 可按状态上报多次；只有 completed 且奖励到账时 reward_granted=true。
buff_use
玩家使用“直接找到卡皮巴拉”或“提示建议”且道具实际生效时上报。
buff_type:enum（direct_find／hint）；source:enum（initial_free／level_config_free／rewarded_ad）；applied:bool；inventory_before:int；inventory_after:int
direct_find 在成功揭示卡皮巴拉后上报；hint 在提示层展示时记录 applied=false，点击 Apply 后补记 applied=true。
coin_change
预留：仅在后续版本正式接入金币后上报。V1 当前无金币系统，默认不上报。
change_type:enum（gain／spend）；source:string；change_amount:int；balance_after:int
保留事件名避免后续改表；不得用该事件代替分数、生命值或 Buff 次数。

[366] 6.4 字段枚举与最小约束

[367] • placement_id：direct_find（直接找到卡皮巴拉）、hint（提示建议）、revive（复活）、level_start_free（关卡开始免费广告）、coin_double（金币翻倍；当前无金币时不启用）。

[368] • buff_type：direct_find、hint。免费赠送与观看广告获得的道具使用相同枚举，通过 source 区分来源；source 增加 level_config_free（Pawdoku 逐关免费配置）。

[369] • fail_reason：life_zero、quit、unknown。V1 不上报逐格错误坐标、错误颜色或每次扣血明细。

[370] • duration_sec 使用整数秒，最小值为 0；attempt_no 从 1 开始；life_remaining 不得小于 0。

[371] • offer_id 在用户点击广告入口时生成，并在 ad_offer_shown 与后续所有 ad_result 中保持一致。

[372] • 不得上传姓名、手机号、广告标识符原值、精确位置、聊天内容或其他可直接识别个人身份的信息。

[373] 新增功能埋点位置：

[374] • 进入关卡并完成 Pawdoku 逐关配置加载时上报 level_start，携带 direct_find／hint 库存、direct_find 是否可见及关卡开始免费广告是否可用。

[375] • 点击 direct_find、hint、revive 或关卡开始免费广告入口并发起广告请求时上报 ad_offer_shown；广告开始、完成、中断或失败时使用同一 offer_id 上报 ad_result。

[376] • direct_find 实际揭示卡皮巴拉、hint 展示或应用提示时上报 buff_use，并记录来源、使用前后库存和 applied。免费次数仅发放但未使用时不触发 buff_use。

[377] • 所有关卡、道具、广告、失败和复活事件携带 pawdoku_config_version，以便核对实现所使用的冻结配置。

[378] 6.5 上报与验收要求

[379] • 事件必须在对应业务结果确定后上报，避免先上报成功、后因流程失败而造成数据虚高。

[380] • 客户端需要防止重复上报。first_open、单次 level_start、单次 level_end、单次奖励到账应具备幂等约束。

[381] • 断网时允许本地缓存并在恢复网络后补报；补报保留原 event_time、user_id、session_id 和 offer_id。

[382] • 开发联调时逐事件核对触发次数、必填字段、枚举值、空值规则和前后事件关系；测试环境与正式环境的数据必须隔离。

[383] • 上线前使用至少一条完整路径验收：首次打开 → 完成引导 → 开始关卡 → 失败 → 重试 → 使用 Buff → 观看激励广告 → 通关 → 结束 Session。

[384] • 第一版上线后先核对四块看板能否由上述 12 个事件完整计算；若无法回答明确业务问题，再增加事件或字段。

[394] 7.3 初始化、权限与异常处理

[395] 初始化顺序：Loading 阶段只初始化维持游戏运行所必需的基础服务（本地存储、崩溃监控、远程配置缓存读取）。数据分析 SDK 在用户点击 Accept 后初始化，广告 SDK 在 Tracking 环节结束后初始化；此后每次启动，在同意状态确认后即可初始化。广告个性化、Tracking 和通知能力必须在对应授权完成后再启用。

[396] 权限流程：弹窗顺序沿用“Loading → Data Use → Terms & Privacy → Notifications → Tracking → Home”；用户拒绝非必要权限后仍可进入并完成核心游戏。

[397] 异常处理：任一第三方 SDK 初始化失败、超时或无网络时，不得阻塞首页和关卡进入；客户端记录失败原因，并在后续合适时机静默重试。

[398] 环境隔离：测试、预发布和正式环境使用独立的 App ID、广告位 ID、数据源和开关。测试包必须使用测试广告，禁止产生正式广告收益或污染正式数据。

[399] SDK 清单：所有 SDK 的名称、版本、用途、采集字段、服务商、隐私政策链接和关闭方式需形成 SDK 清单，并在每次发版前由产品、开发和隐私负责人共同复核。

[404] 存档范围：关卡答案、颜色区域等关卡数据全部来自安装包内的关卡配置，不写入存档，也不由远程下发；存档只记录玩家状态。

[405] 断点恢复：应用被系统回收或强制退出后再次进入，应恢复关内进度中的棋盘、生命值和分数；玩家主动退出关卡（返回首页）后是否保留进度，以解包原游戏为准。

[406] 写入可靠性：存档采用原子写入（先写临时文件再替换）并保留上一份有效备份；读取失败或校验不通过时回退到备份，仍无法恢复才按新用户默认状态启动，并记录错误，不得导致崩溃或闪退。

[407] 版本迁移：存档带 schema 版本号；客户端升级后必须能读取并迁移旧版本存档，迁移失败时保留旧文件；不得因迁移改变已通关记录、道具库存和签到状态。

[408] 卸载重装：V1 不提供进度找回，重装后关卡进度、道具和签到均重置。

[409] 日期与防刷：签到按项目统一时区的自然日判断，同一自然日只能领取一次；联网时优先使用服务器时间，离线时使用本地时间，但本地时间回拨不得造成重复发奖。

[410] 隐私：存档与本地缓存不写入姓名、手机号、精确位置或广告标识符原值等可直接识别个人身份的信息。

[418] 8.1 商业化范围与原则

[419] 广告类型：V1 正式商业化广告分为插页广告（Interstitial）和激励广告（Rewarded）两类。横幅广告仅保留版面预留，默认关闭；如需上线，需单独评审广告位、频控和遮挡风险。横幅关闭时预留区域按 UI 稿呈现（留白或收起），但棋盘与道具按钮的位置不得因此变化。

[420] 展示原则：广告不得遮挡棋盘操作、系统手势区域或关键结算信息；同一时刻只能展示一个广告流程，广告展示期间冻结关卡输入。

[421] Pawdoku 配置映射：至少导入 direct_find_enabled、direct_find_unlock_level、direct_find_initial_free_count、direct_find_inventory_by_level、hint_inventory_by_level、level_start_free_ad、failure_flow_id 和对应激励广告开关。默认值由冻结版 Pawdoku 配置生成，不在代码或本文中写死。

[422] 远程控制：所有广告触发、开关、起始关卡、免费次数和频控均由远程配置控制（键名与默认值见 8.5）。

[423] 8.2 插页广告

[424] 起始关卡：interstitial_start_level 默认为和Pawdoku一样。

[425] 触发时机：仅在 result=win 的胜利结算页展示：玩家点击“下一关”或返回首页时，先展示插页广告，广告关闭后再执行原操作。失败、复活弹窗、教学遮罩和权限流程中不得插入插页广告。

[426] 展示频率：每次胜利结算最多展示 1 次，由 interstitial_frequency 控制（每 N 次符合条件的通关展示 1 次，默认 N=1）。同一关重试、前后台切换、广告加载失败或结算页重复打开不得再次触发。

[427] 第 10 关衔接：第 10 关首次通关时，顺序为“胜利结算 → 插页广告 → A New Challenge! 弹窗 → 第 11 关”，插页广告不得叠在难度提示弹窗之上。

[428] 无奖励与失败处理：插页广告不提供游戏奖励。广告无填充、加载超时（ad_timeout_sec）或展示失败时直接跳过，不阻塞结算和下一关流程。

[429] 关闭与恢复：插页广告开始展示后按 SDK 规则提供关闭入口；关闭后恢复游戏音频与页面状态，不自动触发其他广告。

[430] 8.3 激励广告位（和Pawdoku一致）

[431] 适用功能：激励广告用于 direct_find（直接找到卡皮巴拉）、hint（提示建议）、revive（复活）以及 Pawdoku 配置中存在的关卡开始免费广告入口。各入口的出现关卡、奖励和次数以冻结版 Pawdoku 配置为准；placement_id 用于埋点、远程开关和收益拆分。

[432] 入口与库存：direct_find、hint 按钮有库存时显示剩余次数，点击后直接消耗 1 次并执行功能；库存为 0 时角标切换为绿色视频图标，点击后直接拉起激励广告，不增加二次确认弹窗。revive 的入口为失败弹窗中的复活按钮，点击后直接拉起激励广告。

[433] 加载与失败：广告尚在加载时，按钮进入短暂 Loading 状态并防止重复点击；超过 ad_timeout_sec 仍未就绪，或无填充、无网络、展示失败时，提示 Video unavailable，且不扣次数、不发奖励、不改变棋盘状态。

[434] 奖励判定：只有收到 SDK 的完整观看与奖励回调后才执行功能。offer_id 在广告入口触发时生成（定义见 8.6），同一 offer_id 只发放一次；用户中途关闭、播放失败或回调缺失时不发放奖励。

[435] 奖励台账：收到奖励回调后先写入奖励台账（见 7.4）再执行功能；若在“奖励已到账、功能未执行”时被中断，重启后为 direct_find 或 hint 补发 1 次对应道具库存，revive 不补发。

[436] 8.4 三个激励广告功能结果

[437] 直接找到卡皮巴拉：收到有效奖励回调后，随机揭示 1 只尚未找到的正确卡皮巴拉，更新进度与分数，不扣生命值，不自动生成 X。若回调到达时本关已结束或不存在未找到卡皮巴拉，则不修改棋盘，并按奖励台账补发 1 次 direct_find 库存。

[438] 复活：生命值恢复至本关满值（以解包配置为准），保留已找到卡皮巴拉、玩家手动 X、红色错误 X、分数和当前棋盘进度。同一局不限制复活次数；复活后再次失败时，仍弹出复活广告页面。玩家可重复观看广告复活；玩家主动选择 Restart 后，重新开始本关。

[439] 提示建议：弹出提示层，展示排除理由并高亮建议标记的格子；只有用户点击 Apply 后才批量写入 X。观看广告本身不得直接修改棋盘。提示层弹出即扣除 1 次库存，关闭提示层而未点击 Apply 时不返还次数（与 buff_use 中 applied=false 的记录一致）。

[440] 免费次数：direct_find、hint、revive 以及关卡开始免费广告的次数、重置节点和跨关规则均与冻结版 Pawdoku 配置一致。

[441] 8.5 广告状态、预加载与频控

[442] 预加载：按冻结版 Pawdoku 对应关卡需要的 direct_find、hint、revive 和 level_start_free 广告位进行预加载，展示后立即补充加载；如聚合平台要求按广告单元分别配置，则每个启用广告单元各保持 1 个已加载实例。不得因预加载影响首屏进入速度和棋盘帧率。

[443] 音频：广告展示期间暂停背景音乐并保留原开关状态；广告关闭或失败后恢复此前音频状态，不重复播放关卡开场音效。

[444] 打断处理：应用进入后台、来电或系统弹窗打断广告时，以 SDK 最终回调为准；未确认奖励时不得自行补发。

[445] 幂等保护：连续快速点击广告按钮、重复奖励回调和网络重试均需具备幂等保护，避免重复展示、重复扣次数或重复发奖。

[446] 配置生效：远程配置在下一次进入关卡或下一次启动时生效，不改变正在进行的关卡与广告流程；拉取失败沿用上次成功配置，其次使用包内默认值。

[447] 8.6 广告数据与收益回传

[448] 事件口径：广告事件沿用 ad_offer_shown 与 ad_result（见 6.3），并补充 ad_type（rewarded／interstitial）、network、ad_unit_id 三个字段；level_id 使用公共参数，展示结果使用 ad_result.status，奖励是否到账使用 reward_granted，不另设 result 与 is_rewarded 字段。

[449] ad_offer_shown 触发点：激励广告不设二次确认弹窗，因此 ad_offer_shown 与 offer_id 在广告入口触发时生成并上报。

[450] 激励广告统计：在上述基础上，统计完整观看、奖励回调、奖励到账和功能执行结果（reward_granted、buff_use）。

[451] 收益回传：SDK 提供展示级收益回传时，记录 revenue、currency、precision 和 country；收益字段不得由客户端自行估算。回传通道（随 ad_result 上报，或由聚合平台直连分析平台）在联调前确定，避免同一次展示重复计收益。

[452] 商业化看板：至少包含 Ads per DAU、插页广告展示率、激励广告接受率、完成率、各广告位 ARPDAU／收益及无填充率，并支持平台、版本、国家和关卡筛选。插页广告展示率 = 插页 ad_result 中 status=started 的 offer 数 ÷ 插页 ad_offer_shown 的 offer 数。

[453] 8.7 广告验收场景

[454] 激励广告场景：按 Pawdoku 的 L1–20 逐关配置分别验证 direct_find、hint、revive 和 level_start_free 的显示状态、免费次数、广告状态及奖励结果，并覆盖无填充、无网络、加载超时、中途关闭、完整观看和重复回调。

[455] 结果一致性：验证激励广告成功后功能只执行一次，失败时棋盘、生命值、道具次数和分数均保持不变；在“奖励已到账、功能未执行”时强制退出 App，重启后按奖励台账处理。

[456] 开关与降级：验证广告总开关、各广告位开关和横幅开关关闭时的表现符合 8.1；远程配置拉取失败时使用缓存或包内默认值。

[457] 环境与隐私：验证 iOS 的广告位 ID、测试模式、ATT 与适用地区同意流程（允许／拒绝）、收益回传和远程开关正确，正式包不包含测试广告标识。

[458] 音频：验证广告展示前后背景音乐的暂停与恢复正确，不重复播放关卡开场音效。
